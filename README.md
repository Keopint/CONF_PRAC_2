# Dependency Graph Visualizer (Variant 18)

## Общее описание
Инструмент командной строки для визуализации графа зависимостей менеджеров пакетов.
Текущая версия: **Этап 4 (Дополнительные операции)**.

## Описание функций и настроек

Приложение поддерживает следующие опции командной строки:

* `--package` (строка) — Имя анализируемого пакета (обязательный параметр).
* `--repo` (строка) — URL-адрес репозитория (например, `https://pypi.org`) или путь к локальному файлу тестового репозитория (обязательный параметр).
* `--test-mode` (флаг) — Режим работы с тестовым репозиторием. Если флаг установлен, параметр `--repo` воспринимается как путь к текстовому файлу.
* `--ascii-tree` (флаг) — Режим вывода зависимостей в формате ASCII-дерева *(будет реализован на Этапе 5)*.
* `--max-depth` (целое число) — Максимальная глубина анализа зависимостей (обязательный параметр, от 1 до 100).

### Формат файла тестового репозитория
Для режима `--test-mode` используется текстовый файл (например, `test_repo.txt`). 
Формат строки: `ПАКЕТ: ЗАВИСИМОСТЬ1 ЗАВИСИМОСТЬ2`.
Имена пакетов должны состоять из больших латинских букв.
Пример:
```text
A: B C
B: D
C: D E
D: A
```

## Сравнение с реальным менеджером пакетов (pip)

Мы реализовали вывод порядка загрузки (установки) зависимостей снизу вверх (от листьев графа к корню).
**Теоретическое сравнение:**
Если выполнить `pip install requests`, pip установит пакеты в примерно следующем порядке:
1. `certifi`
2. `charset-normalizer`
3. `idna`
4. `urllib3`
5. `requests`

Наш инструмент с флагом `--install-order` выдает такую же логику (сначала те, от кого зависят другие).

**Объяснение расхождений:**
1. **Маркеры окружения (Environment Markers).** PyPI возвращает зависимости с условиями (например, `idna; python_version >= "3.8"`). Мы отрезаем эти условия (функция `clean_package_name`), из-за чего в наш граф могут попасть пакеты, которые на конкретной ОС или версии Python не будут установлены реальным `pip`.
2. **Разрешение конфликтов версий (Dependency Resolution).** `pip` использует сложный алгоритм (backtracking) для подбора совместимых версий. Наш инструмент строит граф на уровне *имен* пакетов, не учитывая конфликты версий.
3. **Циклические зависимости.** Если в PyPI найдутся пакеты, зависящие друг от друга (что редкость, но бывает), `pip` выдаст ошибку, а наш алгоритм благодаря множеству `visited` просто проигнорирует петлю и выведет корректный порядок загрузки.
